# Phase 1b: 「主役 = WaveTrend / ADX、補助 = スクイーズ」仮説の検証

- 対象: BTCUSDT, ETHUSDT, SOLUSDT / 5m, 15m, 1h
- 期間: 2025-01-01 .. 2026-06-01（Hold-out 2026-06-01..2026-08-31 は封印・未使用）
- EMA の立ち上がりを避けるため、先頭 **500 本**を解析対象外にした

Phase 1 の結論（スクイーズ解放時の `val` の符号に方向情報なし）は変更していない。
これは別の仮説の検証であり、再挑戦ではない。

## 0. 事前に確定した判定ルール（実行前に固定・後から緩めていない）

| 項目 | 問 1（主役単体）| 問 2（補助の価値）|
|---|---|---|
| セル数 | 36（2 主役 × 3 時間足 × 6 ホライズン）| 18（合格主役の 3 時間足 × 6 ホライズン）|
| 有意水準（Bonferroni）| 0.05/36 = **0.00139** | 0.05/18 = **0.00278** |
| 合格条件 | 95%CI 下限（bps）> 1.0 bps かつ補正後に有意 | 差の 95%CI 下限 > 0 かつ補正後に有意 かつ S1 の絶対水準 > 1.0 bps |
| 主検定の単位 | ATR 正規化リターン（コスト判定のみ bps）| 同左 |

**Phase 1 のレビューを受けた変更**: 主検定を ATR 単位にした。
Phase 1 では bps でプールしたため値動きの大きい SOL に平均が引っ張られた
（1h/N=48 の +35.2 bps は SOL 単独で +78.8 bps だった）。
ATR 単位なら「その銘柄の普段の値動きの何倍動いたか」で公平に比較できる。

問 2 の「解放直後」は **直近 6 本以内に黒→灰の解放があった**
と定義し、事前に固定した。k = 3 / 12 は記述統計としてのみ併記し、判定には使わない。

**不利な点**

- この 36 セルは、実行前に「記述統計のみ・判定には使わない」と

- 仮にこの族へ同じ Bonferroni（0.05/36 = 0.00139）を

- 時間足を跨いだ一貫性がない（同じ定義でも 5 分足・1 時間足では

- 窓が重なっているため、実効標本は表の n より少ない
- そして最も重要な点: **閾値 20 が不合格で 25 が良かったから 25 を採る、
  というのは依頼書が明示的に禁じた「パラメータを振って良い方を選ぶ」
  行為そのもの**である

**したがって Phase 1b の判定は不合格のまま変えない。**

この系列を本気で検証したいなら、それは**新しい事前登録を要する別プロジェクト**
になる。封印中の Hold-out（2026-06-01 .. 2026-08-31）は、まさにそのために
取ってある。着手するかどうかの判断は依頼者に委ねる。

## 6. 最終判定

### 中止基準に到達 — Phase 1b をここで終了する

事前に確定した合格条件を満たしたセルは、WaveTrend / ADX とも **0 / 18**（合計 0 / 36）だった。

「作者が言及した ADX / WaveTrend が主役で、スクイーズはその補助だった」
という仮説は、**主役の側で成立しなかった**。標準設定の WaveTrend クロスにも
ADX の 20 上抜けにも、往復コストを超える方向情報は確認できなかった。

補助（スクイーズ）で選別しても、元の主役に情報が無い以上は情報が生まれない。
したがって問 2 には進まない。

### 言えること / 言えないこと

- 言える: **標準設定の** WaveTrend / ADX を、**この定義のシグナル**で使う限り、
  方向情報は確認できない。スクイーズを補助に足す前段が成立していない。
- 言えない: 「WaveTrend / ADX に一切情報が無い」とは言えない。
  パラメータ（10/21、14、閾値 20）は作者が言及した標準設定に固定しており、
  最適化していない。これは意図的な制約であり、
  中止基準到達後にパラメータを振り直すのはデータスヌーピングになる。
- WaveTrend の `wt2` は `wt1` の 4 本移動平均にすぎないため、
  このクロスは「wt1 が直近 4 本平均を上下に横切った」以上の意味を持たない。
  クロス頻度が高く（5 分足でバーの十数 % がシグナル）、
  ほぼ全バーに賭けているのに近い状態になる点は、設計上の限界として記録しておく。
