## 0. 何を変えたか

変更したのは `phase1_event_study.py` の解放イベント判定 1 行のみ。

```python
# 変更前 (旧定義): 「黒でなくなった」= 灰と青の両方を含む
release[1:] = (~sqz_on[1:]) & sqz_on[:-1]

# 変更後 (原典): 「黒 -> 灰」だけ
release[1:] = sqz_off[1:] & sqz_on[:-1]
```

| 定義 | 内容 |
|---|---|
| `any` | 黒 -> 黒以外 (灰 + 青)。旧定義 |
| `gray` | 黒 -> 灰 (sqz_off)。原典 Carter / LazyBear の推奨 |
| `blue` | 黒 -> 青 (no_sqz)。gray から除外された側 |

**変えていないもの**: `HORIZONS`, `SYMBOLS`, `INTERVALS`, 期間（2025-01-01 .. 2026-06-01）, コスト前提, 合格条件（Bonferroni 補正後 p < 0.00278 かつ 95%CI 下限 > 1.0 bps）。

## 2. なぜ差が出ないのか（構造的な理由）

既定パラメータでは BB 期間と KC 期間がどちらも 20 なので、
BB の中心線 `basis` と KC の中心線 `kc_ma` はどちらも `SMA(close, 20)` で**同じ値**になる。
すると原典の 2 条件は同じ 1 本の不等式に帰着する。

```
upperBB < upperKC  <=>  basis + dev < basis + rangema*1.5  <=>  dev < rangema*1.5
lowerBB > lowerKC  <=>  basis - dev > basis - rangema*1.5  <=>  dev < rangema*1.5
```

つまり `sqz_on = (dev < rangema*1.5)`、`sqz_off = (dev > rangema*1.5)` であり、
`no_sqz`（青）は両者がちょうど等しいときだけ成立する。
小数の完全一致なので実質的に発生しない。実データで確認した結果:

| 銘柄 | 時間足 | max|basis − kc_ma| | 青(no_sqz)の本数 | sqz_on == (dev < rangema×1.5) |
|---|---|---:|---:|---|
| BTCUSDT | 5m | 0.000e+00 | 0 | 一致 |
| BTCUSDT | 15m | 0.000e+00 | 0 | 一致 |
| BTCUSDT | 1h | 0.000e+00 | 0 | 一致 |
| ETHUSDT | 5m | 0.000e+00 | 0 | 一致 |
| ETHUSDT | 15m | 0.000e+00 | 0 | 一致 |
| ETHUSDT | 1h | 0.000e+00 | 0 | 一致 |
| SOLUSDT | 5m | 0.000e+00 | 0 | 一致 |
| SOLUSDT | 15m | 0.000e+00 | 0 | 一致 |
| SOLUSDT | 1h | 0.000e+00 | 0 | 一致 |

`basis` と `kc_ma` の差は浮動小数点の丸め誤差レベルで、青のバーは全データセットで 0 本。
`sqz_on` が単一の不等式 `dev < rangema×1.5` と完全一致することも確認した。

**注意**: これは BB 期間 = KC 期間 のときに限った話である。
両者を別の値にすると中心線がずれ、青の状態が実際に発生しうる。
ただし今回は「定義の修正」のみが依頼範囲であり、期間は変更していない。

## 4. 除外された側（黒→青）の符号方向リターン

**イベント数 0 件のため集計不能。**

依頼の目的は「黒→灰が正、黒→青が負、という逆向きの構造があるか」の確認だった。
そもそも黒→青が 1 件も存在しないため、**逆向きの構造は存在しない**。
旧定義に混ざっていた「余計なイベント」は 1 件も無かったので、
定義の違いは Phase 1 の結論にまったく影響していない。
